# WeaverDeck v0.18.0 — runtime testing update

Adds source Mute To destination controls, Audio Engine Restart and Audio Buffer Size actions for buttons and Smart Scenes. Actions are grouped alphabetically by function.

## Runtime checks completed — 5 September 2026

Tested by djbauer using OpenDeck and PipeWeaver on Linux, with plugin logs reviewed.

- Source Mute To Set, Toggle and All: Browser slot B → Headphones. User confirmed the dropdown followed the controls; every recorded action succeeded.
- Audio Buffer Size buttons: changes to 512 and 256 samples succeeded after engine recovery.
- Audio Engine Restart button: two successful executions.
- Restart Scene: engine recovery completed in 4,014 ms, followed by Brave application volume changing from 91% to 40%, confirmed by status.
- Mute To Scene: Set Browser B → Headphones, followed by Source B Mute; both runs completed with zero validation errors or warnings. These logs confirm command success; they do not independently measure destination audio.
- Buffer Size Scene: 512 samples applied with recovery in 4,010 ms. Repeating the same setting completed in 1 ms, consistent with the intended no-op.

## Playback and recovery behaviour

Engine restarts and buffer changes can pause Brave playback. The user confirmed clicking Play immediately restores audio; no browser restart is needed. Engine readiness does not guarantee automatic application playback resumption.

Temporary HTTP 503 responses (“PipeWire manager is not running”) occurred during engine resets, followed by recovery and successful action completion.

If an application stream is absent when a Scene application step executes, the existing missing-application behaviour can skip it even though the Scene completes. An OK/COMPLETE message alone is not proof that playback resumed.

Mute To configures destinations rather than activating mute. PipeWeaver may unmute the slot when destinations change; place Source Mute afterward when needed.
