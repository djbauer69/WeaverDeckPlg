updated separately on DeviceVolumeChanged. The plugin now waits for bounded
physical readback confirmation without retrying commands. The user and retest log
confirm this fix on both physical inputs.

their editors directly, and the old wrapper path navigates existing profiles to
the same direct editor using OpenDeck's normal load/connect handshake. Shared
Button Text, action header and compact styling are applied in place. Scene's two
remaining internal frames retain automatic sizing and use compositing. The user
confirmed successful OpenDeck rendering after installing this build.

## 7 September: deletion/reselection follow-up

The user reported clipping after deleting a button, selecting another plugin
button, and switching through an empty key. The earlier direct-editor fix did not
cover this sequence. The uploaded report log was
`com.pipeweaver.opendeck.sdPlugin(20260907-023353).log`; it did not record inspector
selection events, so it could not establish the WebView rendering cause.

The follow-up forwards inspector appear/disappear events to the matching editor,
adds an inspector-ready handshake, and requests a temporary scroll repaint even
on short pages, restoring styles/scroll position afterward. It adds `[Inspector]`
lifecycle and redraw diagnostics.

The user subsequently confirmed: “Okay that works”, and authorized merging the
update. [PR #8](https://github.com/djbauer69/WeaverDeckPlg/pull/8) was merged at
`ebbfa1f6b9896bf433128664c499dabf20cf33af`. This is user visual confirmation; no new
post-fix log was supplied with that confirmation.
